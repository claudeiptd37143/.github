<p>配置静态住宅线路，麻烦的从来不是记不住那几个数字，而是不知道每个参数改了会牵动什么。出口地址、租期、白名单、健康检查，这几项互相牵连：白名单写错会让固定出口形同虚设，健康检查间隔设得太短会把正常抖动判成故障。下面按说明书的方式逐项列出参数、典型取值、作用和误设后果，给一份可以直接对着填的清单。</p>

<h2>一、这份说明书覆盖哪四类参数</h2>
<p>四类：第一类是出口标识，决定流量从哪个地址出去；第二类是租期与续约，决定这个地址能保持多久；第三类是通行控制，也就是白名单与鉴权；第四类是可用性判定，包括健康检查与切换策略。四类里前三类决定「能不能用」，第四类决定「断了之后多快能恢复」。</p>
<p>建议按这个顺序配置。先把出口固定下来，再确认租期，然后开放通行，最后才配切换。顺序反了会反复返工，比如先配了白名单再换出口，白名单就全要重写一遍。</p>

<h2>二、固定出口相关参数</h2>
<p>固定出口的本质是把出口地址与会话绑定，绑定失效的常见原因不是地址变了，而是租期到期后系统自动分配了另一个地址。所以租期参数比地址本身更值得关注。</p>

<h3>租期长度与续约方式怎么配</h3>
<p>按月租用适合短期验证，能快速止损；季度或年付单价更低，但一旦服务商调整资源，迁移成本更高。比较稳妥的做法是首月按月，确认稳定后再转长期。无论哪种，都建议开启自动续费并在日历里提前一周提醒，因为地址回收往往发生在到期当天，而不会提前通知。</p>

<h2>三、白名单的三种形态与失效条件</h2>
<p>白名单不是只有一种。源地址白名单限制谁能连，账号口令限制用什么凭证连，目标白名单限制能访问哪些地址。三者可以叠加，叠加之后排查难度也上升，所以每加一层都要记下配置时间。</p>

<h3>源地址白名单最怕地址漂移</h3>
<p>源地址白名单要求你的本地出口固定，一旦本地宽带重拨换了地址，白名单立刻失效，表现为「昨天还能用，今天全部超时」。解决办法有两个：给本地线路申请固定地址，或者改用账号口令鉴权。前者稳定但受限于本地运营商，后者灵活但凭证管理要跟上。</p>
<h3>账号口令与白名单的先后顺序</h3>
<p>两者同时开启时，多数实现会先校验源地址再校验凭证。这意味着地址不对时，凭证再正确也连不上，而报错信息往往只有「认证失败」，容易误判成密码错误。排查时先用 <code>curl -x</code> 带凭证发一个请求，看返回是拒绝连接还是认证失败，就能区分是哪一层拦住了。</p>

<h2>四、故障切换的判定、动作与回切</h2>
<p>切换策略由三个参数决定：判定阈值、切换动作、回切条件。三者缺一不可，只配前两个会导致线路恢复后仍停在备用线上，长期跑着低质量路径却没人发现。</p>
<h3>健康检查间隔与连续失败次数的配合</h3>
<p>间隔太短会误判。家宽线路偶发丢一两个包很正常，如果每五秒检查一次、失败一次就切，一天可能切十几次。建议间隔三十秒、连续三次失败才判定，这样单次抖动不会触发切换，真正断线也能在两分钟内被发现。</p>

<h3>切换后必须重建会话</h3>
<p>切换只改变路径，不改变已经建立的连接。原有的 TCP 会话仍然指向旧出口，切换后表现为「新请求正常、老页面卡死」。正确做法是切换后主动断开并重建长连接，或者在应用层设置较短的保活间隔，让旧会话尽快超时。</p>

<h2>五、按顺序填参数并做回归验证</h2>
<h3>填完之后的三项回归</h3>
<p>第一项，确认出口地址与配置一致，用 <code>curl ifconfig.me</code> 或服务商提供的查询页核对；第二项，从白名单外的地址试连一次，确认真的被拒绝，避免白名单写成全放行；第三项，手动断一次主线路，记录从断到恢复的实际耗时，与配置的阈值对比。</p>
<p>三项都通过之后，把配置导出备份一份，并在文件名里写明日期。后续每次改动都留一版，出问题时能快速回退到上一个可用状态。</p>

<h2>常见问答</h2>
<h3>固定出口会不会因为服务商维护而变？</h3>
<p>答：正规服务商在维护前通常会提前通知，但小规模服务商未必。可以用一个每天执行一次的脚本记录出口地址，出现变化时发提醒，这样比自己猜测更可靠。</p>
<h3>白名单能不能填网段而不是单个地址？</h3>
<p>答：多数支持，但网段越大风险越高。填一个 /24 意味着同网段的两百多个地址都能连，等于把限制削弱了很多。建议只填当前使用的单个地址，变动时手动更新。</p>
<h3>健康检查会不会被目标当成攻击？</h3>
<p>答：三十秒一次的频率对单目标来说很低，一般不会。但如果检查的是第三方站点而不是自有服务，应改为检查自有节点或改用更轻量的方式，避免给他人造成负担。</p>
<h3>切换失败最常见的配置错误是什么？</h3>
<p>答：备用线路的凭证沿用了主线路的，而服务商按凭证区分线路，导致切换后认证不通过。配置时把两套凭证分开管理，并在切换日志里打印实际使用的凭证标识。</p>
